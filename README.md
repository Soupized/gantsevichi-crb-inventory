# Учёт компьютеров и техники — Ганцевичская ЦРБ

Приложение для учёта компьютеров и периферийного оборудования библиотеки. Позволяет вести инвентарные карточки, отслеживать статусы (в эксплуатации, в ремонте, на складе, списано), привязывать устройства к компьютерам, искать и фильтровать записи, делать резервные копии и обмениваться данными через CSV.

## Возможности

- **Компьютеры:** инвентарный номер, модель/сборка, процессор, видеокарта, ОЗУ, накопитель, материнская плата, ОС, расположение, ответственный, даты ввода и списания/вывода, причина списания, примечания, статус.
- **Периферия:** тип (мышь, клавиатура, монитор, принтер, сканер, ИБП, другое), инвентарный и серийный номера, производитель, модель, привязка к компьютеру, даты/причина списания/вывода, примечания, статус.
- **Статусы:** «В эксплуатации», «В ремонте», «На складе», «Списан» — для компьютеров и устройств, с фильтрацией в интерфейсе.
- **Поиск и фильтры:** по ключевым полям, по статусу, типу устройства и привязке к компьютеру.
- **Резервное копирование:** скачивание и восстановление полной копии базы данных в формате **SQLite `.db`**.
- **Экспорт/импорт:** **CSV (UTF-8)** для компьютеров и периферии — открывается в Excel, LibreOffice Calc, Google Sheets. Импорт добавляет новые записи и обновляет существующие по инвентарному номеру.
- **Работа по локальной сети:** приложение можно запустить на одном ПК/сервере и открывать из браузера на других компьютерах в той же сети (несколько пользователей).

## Требования

- Windows (для запуска через `start.cmd`; серверная часть на .NET 8 кроссплатформенная, но сценарий развёртывания ниже описан для Windows).
- Для сборки и запуска из исходников:
  - [.NET SDK 8.0](https://dotnet.microsoft.com/download/dotnet/8.0)
  - [Node.js](https://nodejs.org/) 18+ (с npm)

Проверка:

```powershell
dotnet --version
node --version
npm --version
```

## Быстрый запуск (один компьютер)

В корне проекта:

```powershell
.\start.cmd
```

Скрипт установит зависимости клиента (при необходимости), соберёт интерфейс, применит миграции БД и запустит приложение. По умолчанию оно будет доступно:
- на этом ПК: <http://localhost:5169>
- с других устройств в локальной сети: `http://<IP-этого-ПК>:5169` (см. раздел ниже).

> Если на ПК нет системного `dotnet`, скрипт попробует использовать `%USERPROFILE%\.dotnet\dotnet.exe`.

Ручной запуск (после сборки клиента в `server/wwwroot`):

```powershell
cd client
npm install
npm run build
cd ..\server
dotnet run --no-launch-profile --urls "http://0.0.0.0:5169"
```

## Запуск на сервере для нескольких пользователей (локальная сеть)

Этот режим позволяет поставить приложение на выделенный ПК/сервер в организации и работать с ним одновременно с нескольких рабочих мест.

1. **Установите приложение на сервер** (ПК, который будет постоянно включён во время работы) и выполните `.\start.cmd` либо настройте автозапуск.
2. **Адрес прослушивания.** По умолчанию `start.cmd` запускает сервер на `http://0.0.0.0:5169`, поэтому он принимает подключения по сети. Чтобы ограничить доступ только этим компьютером, перед запуском задайте:
   ```powershell
   set APP_URLS=http://localhost:5169
   .\start.cmd
   ```
3. **Узнайте IP-адрес сервера** в локальной сети (например, `ipconfig` → IPv4-адрес) и сообщите его пользователям. Рекомендуется закрепить IP на сервере/роутере (статический или DHCP-reservation).
4. **Откройте порт в брандмауэре Windows** на сервере (TCP 5169, входящие). Пример (PowerShell от имени администратора):
   ```powershell
   New-NetFirewallRule -DisplayName "Gantsevichi CRB Inventory" -Direction Inbound -Protocol TCP -LocalPort 5169 -Action Allow
   ```
5. **Подключение клиентов.** На других компьютерах (и при необходимости на телефонах в браузере, при подключении к той же сети) откройте:
   ```
   http://<IP-сервера>:5169
   ```
   Отдельно устанавливать приложение на клиентские ПК не нужно — достаточно браузера.

### Важные замечания по совместной работе

- **Нет встроенной авторизации.** Любой пользователь, имеющий сетевой доступ к адресу приложения, может просматривать и изменять данные, а также скачивать/восстанавливать резервные копии. Используйте только в доверенной внутренней сети (и при необходимости ограничьте доступ средствами сети/брандмауэра/VPN).
- **Общая база данных.** Все пользователи работают с одной базой `server/library.db` на сервере. Для многопользовательской работы включён режим SQLite WAL, что улучшает параллельное чтение/запись, однако SQLite не рассчитан на высокую конкурирующую нагрузку — для небольшого числа сотрудников библиотеки этого обычно достаточно.
- **Бэкапы.** Перед массовым импортом, восстановлением из копии и обновлениями приложения скачивайте резервную копию `.db`. После восстановления базы другим пользователям нужно обновить страницу в браузере.

## Использование

### Компьютеры
Раздел «Компьютеры»: добавление, редактирование, удаление карточек, просмотр комплектующих, статуса, расположения/ответственного, дат и периферии, привязанной к ПК. При удалении компьютера привязанная периферия остаётся в базе без привязки.

### Периферия
Раздел «Периферия»: учёт устройств с типом, серийным/инвентарным номером, статусом и привязкой к компьютеру (или «без привязки»).

### Статусы
Для компьютеров и устройств доступны статусы: **В эксплуатации**, **В ремонте**, **На складе**, **Списан**. Можно указать дату и причину списания/вывода; по статусам работает фильтр.

### Данные: бэкап и CSV
Кнопка **«Данные»** в интерфейсе:
- **Резервная копия (SQLite `.db`)** — полная копия базы для хранения/переноса/восстановления.
- **Экспорт/импорт CSV (UTF-8)** — отдельные файлы для компьютеров и периферии. Импорт выполняет добавление и обновление по инвентарному номеру (`upsert`). Привязка периферии к компьютеру задаётся колонкой `ComputerInventoryNumber`.

Подсказка по колонкам CSV:
- **Компьютеры:** `InventoryNumber, Status (InUse/InRepair/InStock/WrittenOff), Model, Processor, GraphicsCard, RamGb, Storage, Motherboard, OperatingSystem, Location, AssignedTo, CommissionedOn, DecommissionedOn, DecommissionReason, Notes`
- **Периферия:** `InventoryNumber, Status, Type (Mouse/Keyboard/Monitor/Printer/Scanner/Ups/Other), Manufacturer, Model, SerialNumber, ComputerInventoryNumber, DecommissionedOn, DecommissionReason, Notes`

Даты — в формате `YYYY-MM-DD`.

## Где хранятся данные

База данных: `server/library.db` (SQLite). При запуске автоматически применяются миграции. В режиме WAL рядом могут создаваться файлы `library.db-wal` и `library.db-shm` — их нужно сохранять/копировать вместе с основной базой при ручном резервном копировании.

Файлы `library.db*` не предназначены для коммита в Git (см. `.gitignore`).

## Ограничения

- Интерфейс адаптирован под разные размеры экрана, но не является отдельным мобильным приложением; основной сценарий — работа в браузере на ПК в локальной сети.
- Нет учётных записей и разграничения прав доступа.
- При работе по сети рекомендуется использовать доверенную внутреннюю сеть и выполнять регулярные резервные копии.

## Обновление

1. Сделайте резервную копию базы (`.db`) и, при необходимости, экспорт CSV.
2. Остановите приложение, обновите файлы приложения (код/сборку).
3. Запустите приложение — миграции БД применятся автоматически. Проверьте, что данные на месте.

## Примечание

Проект предназначен для внутреннего учёта техники библиотеки.
