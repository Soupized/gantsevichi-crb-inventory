# Учёт компьютеров и техники Ганцевичской ЦРБ

Веб-приложение для учёта компьютеров и периферийного оборудования библиотеки. Позволяет вести инвентарные записи, хранить характеристики и статусы техники, привязывать устройства к компьютерам, выполнять поиск и фильтрацию, создавать резервные копии базы данных и обмениваться данными через CSV.

## Возможности

- **Компьютеры:** инвентарный номер, модель/сборка, процессор, видеокарта, ОЗУ, накопитель, материнская плата, ОС, расположение, ответственный, дата ввода в эксплуатацию, статус, дата и причина списания/вывода, примечание.
- **Периферия:** тип (мышь, клавиатура, монитор, принтер, сканер, ИБП, другое), инвентарный номер, производитель, модель, серийный номер, привязка к компьютеру, статус, дата и причина списания/вывода, примечание.
- **Статусы:** «В эксплуатации», «В ремонте», «На складе», «Списан» — для компьютеров и устройств, с фильтрацией в списках.
- **Поиск и фильтры:** поиск и фильтрация выполняются на стороне сервера (по номеру, характеристикам, расположению, ответственному, примечаниям и связанным данным). Для периферии доступны фильтры по типу, статусу и привязке к компьютеру.
- **Уникальность инвентарных номеров:** один инвентарный номер может принадлежать только одному компьютеру или устройству. Проверка выполняется с Unicode-нормализацией (включая кириллицу) в приложении и принудительно поддерживается триггерами SQLite на уровне сохранения данных.
- **Авторизация:** доступ к данным защищён паролем; выход из учётной записи доступен в правой части заголовка.
- **Резервное копирование:** скачивание и восстановление полной копии базы данных в формате **SQLite `.db`**.
- **Обмен данными:** экспорт и импорт **CSV (UTF-8 с BOM)** для компьютеров и периферии. Импорт добавляет новые записи и обновляет существующие по инвентарному номеру.
- **Интерфейс:** адаптивная веб-страница для разных размеров экрана, доступная из браузера.

## Технологии

- **Сервер:** ASP.NET Core 8 (Web API), Entity Framework Core 8, SQLite
- **Клиент:** React 18, Vite
- **База данных:** файл `server/library.db` (создаётся/обновляется автоматически при запуске, применяются миграции EF Core)

## Требования

- Windows 10/11

## Быстрый запуск (Windows)

1. Откройте папку проекта.
2. Запустите `start.bat` (рекомендуется) или `start.cmd`.

Скрипт при необходимости собирает клиент и запускает приложение. `start.bat` дополнительно выводит ход работы в консоль, сохраняет лог в `start.log` и при ошибке показывает сообщение и лог, не закрывая окно. По умолчанию приложение доступно:

- `http://localhost:5169` — на этом же компьютере
- `http://<IP-адрес-сервера>:5169` — с других устройств в той же локальной сети

При первом входе требуется пароль. Задайте его переменной окружения `INVENTORY_PASSWORD` до запуска, либо используйте сгенерированный файл `server/auth-password.txt`, который создаётся автоматически при первом запуске без этой переменной.

Чтобы запустить только локально (без доступа из сети), задайте перед запуском:

```bat
set APP_URLS=http://localhost:5169
start.bat
```

## Проверка после изменений

Из корня проекта запустите:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\smoke-test.ps1
```

Скрипт проверяет сборку, запуск сервера, главную страницу, вход/выход, списки и поиск, скачивание и восстановление резервной копии. При первом сбое он печатает лог сервера и завершается с ненулевым кодом.

## Работа с данными

### Резервная копия (SQLite `.db`)

В разделе **«Данные»** доступны:

- **Скачать бэкап (.db)** — полная копия базы данных SQLite.
- **Восстановить из .db** — замена текущей базы содержимым выбранного файла (текущие данные будут заменены).

Рекомендации: создавайте резервную копию перед обновлением приложения, импортом CSV и восстановлением; после восстановления обновите страницу в браузере на всех рабочих местах.

### Экспорт и импорт CSV

- **Экспорт:** отдельные CSV-файлы для компьютеров и периферии (UTF-8 с BOM), подходят для Excel, LibreOffice и Google Sheets.
- **Импорт:** добавляет новые записи и обновляет существующие по инвентарному номеру с Unicode-нормализацией (включая кириллицу). Инвентарный номер должен быть уникальным для всех компьютеров и устройств; дубликаты внутри файла и между таблицами отклоняются.

**Компьютеры (колонки):**  
`InventoryNumber`, `Status` (`InUse`/`InRepair`/`InStock`/`WrittenOff`), `Model`, `Processor`, `GraphicsCard`, `RamGb`, `Storage`, `Motherboard`, `OperatingSystem`, `Location`, `AssignedTo`, `CommissionedOn`, `DecommissionedOn`, `DecommissionReason`, `Notes`

**Периферия (колонки):**  
`InventoryNumber`, `Status`, `Type` (`Mouse`/`Keyboard`/`Monitor`/`Printer`/`Scanner`/`Ups`/`Other`), `Manufacturer`, `Model`, `SerialNumber`, `ComputerInventoryNumber`, `DecommissionedOn`, `DecommissionReason`, `Notes`

Даты указываются в формате `YYYY-MM-DD`. Для привязки периферии к компьютеру используется колонка `ComputerInventoryNumber` (инвентарный номер компьютера).

## Доступ по локальной сети и ограничения

- Приложение рассчитано на работу в доверенной локальной сети. Встроена авторизация по паролю, но разграничения ролей нет — не публикуйте его в открытый интернет без дополнительных мер защиты (HTTPS, reverse proxy, ограничение доступа).
- Интерфейс является адаптивной веб-страницей и может открываться в браузере на разных устройствах в локальной сети (ПК, ноутбук, планшет и т. п.) по адресу сервера; отдельное мобильное приложение не входит в состав проекта.
- База данных SQLite подходит для небольшого количества одновременных пользователей; при высокой конкуренции записей возможны ограничения.
- При восстановлении базы из копии другим пользователям необходимо обновить страницу. Файлы SQLite (`library.db`, `library.db-wal`, `library.db-shm`) следует хранить вместе.

## Структура проекта

- `server/` — ASP.NET Core Web API, EF Core, миграции, контроллеры, работа с SQLite/CSV/резервными копиями
- `client/` — клиентское приложение React (Vite)
- `server/wwwroot/` — статическая сборка клиента для запуска сервером
- `start.cmd` — скрипт сборки клиента и запуска сервера (Windows)
- `start.bat` — оболочка запуска с логом `start.log` и паузой при ошибке
- `scripts/smoke-test.ps1` — практическая проверка основных сценариев
- `CHANGELOG.md` — история изменений
