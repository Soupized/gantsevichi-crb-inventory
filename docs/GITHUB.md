# Публикация проекта на GitHub

Инструкция для первого раза. Все команды и действия можно выполнить без опыта
работы с Git.

## Что такое Git и GitHub

- **Git** — программа, которая хранит историю изменений проекта на вашем
  компьютере.
- **GitHub** — сайт, на котором эта история публикуется, чтобы проект можно было
  показать, открыть с другого компьютера и вести учёт версий.

В проекте уже создан локальный Git-репозиторий и несколько коммитов.

> Коммиты в локальной истории созданы от имени организации «Ганцевичская ЦРБ».
> Для будущих коммитов укажите своё имя и почту (см. вариант 2, шаг 1 или
> настройки GitHub Desktop), чтобы GitHub связывал их с вашим профилем.

## Вариант 1. GitHub Desktop (рекомендуется)

GitHub Desktop — программа с кнопками вместо команд. Для первого раза она проще
всего.

### 1. Создайте аккаунт GitHub

1. Откройте <https://github.com/signup>.
2. Зарегистрируйтесь, подтвердите электронную почту.
3. Запомните имя пользователя (логин) — оно будет в адресе репозитория.

### 2. Установите GitHub Desktop

1. Скачайте программу с <https://desktop.github.com/>.
2. Установите и откройте её.
3. Нажмите **Sign in to GitHub.com** и войдите в свой аккаунт.

### 3. Добавьте готовый проект

1. В GitHub Desktop выберите **File → Add local repository**.
2. Укажите папку `C:\Users\Soup\GantsevichiLibrary`.
3. Нажмите **Add repository**.

Слева появится история коммитов проекта.

### 4. Опубликуйте проект

1. Нажмите кнопку **Publish repository** в верхней части окна.
2. Заполните поля:
   - **Name** — `gantsevichi-library-inventory`;
   - **Description** — `Учёт компьютерной техники Ганцевичской центральной районной библиотеки`;
   - **Keep this code private** — поставьте галочку, если проект не должен быть
     виден всем. Для учебной сдачи обычно нужен публичный репозиторий, тогда
     галочку снимите.
3. Нажмите **Publish repository**.

Через минуту проект появится по адресу
`https://github.com/ВАШ_ЛОГИН/gantsevichi-library-inventory`.

### 5. Заполните описание репозитория

На странице проекта нажмите значок шестерёнки справа от блока **About** и
добавьте:

- **Description**: `Учёт компьютеров и периферии для библиотеки: ASP.NET Core 8, EF Core, SQLite, React, Vite`;
- **Topics**: `aspnet-core`, `entity-framework-core`, `sqlite`, `react`, `vite`,
  `inventory`, `library`, `csharp`, `javascript`.

### 6. Создайте первый релиз

Релиз — это версия проекта, которую видно на GitHub.

1. На странице репозитория откройте **Releases** (справа) → **Draft a new release**.
2. В поле **Choose a tag** напишите `v1.0.0` и выберите
   **Create new tag: v1.0.0 on publish**.
3. **Release title**: `1.0.0 — первая версия`.
4. В большое поле описания вставьте текст из файла
   `docs/RELEASE_NOTES_v1.0.0.md`.
5. Нажмите **Publish release**.

Теперь на GitHub есть тег `v1.0.0` и описание версии.

## Вариант 2. Командная строка

Этот способ полезен, если вы хотите освоить Git. На этом компьютере установлен
портативный Git; после открытия нового терминала команда `git` должна работать.
Если нет — используйте GitHub Desktop.

### 1. Настройте автора коммитов

Укажите те же имя и почту, что в аккаунте GitHub:

```powershell
git config --global user.name "Ваше Имя"
git config --global user.email "ваша-почта@example.com"
```

Если не хотите публиковать настоящую почту, GitHub предлагает служебный адрес
вида `12345678+username@users.noreply.github.com` (он есть в настройках
**Settings → Emails**).

### 2. Создайте пустой репозиторий на GitHub

1. Откройте <https://github.com/new>.
2. **Repository name**: `gantsevichi-library-inventory`.
3. Выберите **Public** или **Private**.
4. Не ставьте галочки **Add a README**, **Add .gitignore**, **Choose a license** —
   файлы уже есть в проекте.
5. Нажмите **Create repository**.

### 3. Свяжите локальный проект с GitHub

В папке проекта выполните:

```powershell
cd C:\Users\Soup\GantsevichiLibrary
git remote add origin https://github.com/ВАШ_ЛОГИН/gantsevichi-library-inventory.git
git push -u origin main
```

При запросе пароля GitHub больше не принимает обычный пароль. Нужен
**Personal Access Token**:

1. GitHub → **Settings → Developer settings → Personal access tokens →
   Tokens (classic) → Generate new token (classic)**.
2. Выберите срок действия и право **repo**.
3. Скопируйте токен и вставьте его вместо пароля.

После отправки обновите страницу репозитория — файлы появятся на GitHub.

## Как вести учёт изменений дальше

Для каждого изменения:

1. Внесите правки в проект.
2. Обновите `CHANGELOG.md`: добавьте пункт в раздел `[Не выпущено]`.
3. Сделайте коммит:
   - в GitHub Desktop — заполните **Summary** и нажмите **Commit to main**;
   - в командной строке:

     ```powershell
     git add .
     git commit -m "feat: добавлен экспорт в Excel"
     git push
     ```

4. Когда накопились изменения и проект проверен, выпустите новую версию:
   - обновите номер версии в `README.md` и `CHANGELOG.md`;
   - создайте коммит `chore(release): 1.1.0`;
   - отправьте его на GitHub;
   - создайте релиз с тегом `v1.1.0` и описанием из `CHANGELOG.md`.

Подробные правила: [VERSIONING.md](VERSIONING.md).

## Что нельзя публиковать

В репозиторий не должны попадать:

- `server/library.db` — база с реальными инвентарными номерами и сотрудниками;
- `server/library.db-shm`, `server/library.db-wal`;
- `client/node_modules` — зависимости устанавливаются командой `npm install`;
- `server/bin`, `server/obj`, `server/wwwroot` — результаты сборки;
- пароли, токены, ключи и другие секреты;
- фотографии документов и персональные данные сотрудников.

Эти файлы уже исключены в `.gitignore`. Проверить, что попало в Git, можно
командой:

```powershell
git status
git ls-files
```

## Если что-то пошло не так

| Проблема | Что сделать |
| -------- | ----------- |
| GitHub Desktop не видит проект | **File → Add local repository**, выбрать папку с файлом `.git` |
| `git` не найден | Открыть новый терминал или использовать GitHub Desktop |
| Ошибка авторизации при `git push` | Создать Personal Access Token с правом `repo` и вставить его вместо пароля |
| Случайно добавлена база данных | Убедиться, что `library.db` указан в `.gitignore`, затем `git rm --cached server/library.db` |
| Нужно отменить последний коммит, но сохранить файлы | `git reset --soft HEAD~1` |
| Нужно посмотреть историю | `git log --oneline --decorate` |
